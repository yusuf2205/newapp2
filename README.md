# newapp2 — Telegram-бот учёта финансовых документов

Бот принимает фото, PDF и .docx чеков, счетов и договоров, распознаёт реквизиты и ведёт
таблицу в Google Sheets: новые договоры добавляет строкой, повторные оплаты
по уже существующему договору — суммирует и пересчитывает остаток.

## Структура

```
main.py            запуск бота (aiogram 3, long polling)
config.py          все настройки из .env
models.py          модель строки таблицы, парсинг и формат сумм
sheets.py          Google Sheets: сотрудники, запись, дедупликация
middlewares.py     подстановка карточки сотрудника (с кэшем на 10 мин)
keyboards.py       инлайн-кнопки
states.py          состояния FSM
handlers/
  registration.py  регистрация: ФИО + должность
  documents.py     приём файла → проект → карточка → запись (личный чат)
  inn_group.py     приём файла в группе → извлечение ИНН → запись без карточки
ocr/
  base.py          интерфейс, промпт извлечения, фабрика движков, эвристики parse_plain_text
  anthropic_engine.py / openai_engine.py / gemini_engine.py / tesseract_engine.py
  docx_engine.py   .docx: текст уже структурирован, OCR не нужен — извлекается напрямую
```

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

### 1. Токен бота
Получите у [@BotFather](https://t.me/BotFather), впишите в `BOT_TOKEN`.

### 2. Google Sheets
1. В Google Cloud Console создайте проект, включите **Google Sheets API** и **Google Drive API**.
2. Создайте **сервисный аккаунт**, скачайте JSON-ключ, положите рядом как `credentials.json`.
   Если организация блокирует создание ключей сервисных аккаунтов
   (`iam.disableServiceAccountKeyCreation`) — создайте проект без организации/в другой
   организации, где эта политика не включена.
3. Откройте вашу таблицу и **дайте доступ на редактирование** почте вида
   `...@...iam.gserviceaccount.com` из этого JSON.
4. ID таблицы — из ссылки `docs.google.com/spreadsheets/d/`**`ID`**`/edit` → в `SPREADSHEET_ID`.

Листы «Данные» и «Сотрудники» создаются автоматически при первом запуске.

### 3. OCR-движок
Переключается одной строкой в `.env`:

| `OCR_ENGINE` | Что нужно | Комментарий |
|---|---|---|
| `anthropic` | `ANTHROPIC_API_KEY`, `pip install anthropic` | по умолчанию; PDF и фото читает нативно |
| `openai` | `OPENAI_API_KEY`, `pip install openai` | PDF рендерится в PNG постранично |
| `gemini` | `GEMINI_API_KEY`, `pip install google-genai` | дешёвый вариант, PDF нативно |
| `tesseract` | `pip install pytesseract` + `apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-uzb` | работает офлайн, но точность заметно ниже |

Добавить свой движок: наследуйте `OcrEngine` из `ocr/base.py`, реализуйте
`recognize(content, mime_type) -> dict` и зарегистрируйте в `get_engine()`.

### 4. Запуск

```bash
python main.py
```

## Как это работает

1. `/start` → если сотрудника нет в листе «Сотрудники», бот спрашивает ФИО и должность
   и сохраняет `[Telegram ID | ФИО | Должность | Дата | Статус]`.
2. Пользователь отправляет фото, PDF или .docx. Распознаются два вида документов:
   - **Бланк заявки на оплату** с полями «№ Заказа/Проект», «Поставщик»,
     «Договор/контракт», «Сумма оплаты в сумах», «Примечание», «Ответственный»;
   - **Обычный документ** (счёт, счёт-фактура, договор, чек) без такой разметки.

   Маппинг в колонки таблицы:
   | Колонка | Источник |
   |---|---|
   | Наименование проекта | «№ Заказа/Проект» (для бланка); иначе выбирается кнопками |
   | Наименование контрагента | «Поставщик» / контрагент документа |
   | Номер контракта с датой | «Договор/контракт» / номер+дата документа |
   | Тип контракта | автоматически: `Импорт`, если валюта суммы не UZS, иначе `Местный` |
   | Наименование товара | **всегда спрашивается в Telegram** отдельным шагом (есть «⏭ Пропустить») |
   | Общая Сумма контракта / Оплачено / Остаток | см. ниже |
   | Валюта | по фактической валюте суммы: UZS, USD, EUR или RUB |
   | Исполнитель | «Ответственный» из документа как есть; если поля нет — ФИО из Telegram |
   | Примечание | код документа (`СО-0736 24.07.2026`, если найден) + кто заполняет в Telegram: `ФИО (должность)` |
   | ИНН | ИНН/СТИР контрагента, если есть в документе (9 цифр) |

   Расчёт сумм для бланка заявки: если «Примечание» — `100% оплата` или `предоплата`
   (или процент не указан), то Сумма = Оплачено = «Сумма оплаты в сумах», Остаток = 0.
   Если указан другой процент (например `30% оплата`), Оплачено = «Сумма оплаты в
   сумах», Сумма контракта = Оплачено ÷ процент × 100, Остаток = Сумма − Оплачено.
   Для обычного документа Сумма/Оплачено берутся из документа напрямую, без пересчёта.
3. Если проект не удалось определить из документа — бот показывает кнопки выбора:
   список из `PROJECTS` + все ранее введённые через «➕ Другой» (хранятся в листе
   «Проекты» — переживают рестарт и общие для всех).
4. Карточка подтверждения → «✅ Подтвердить» / «✏️ Редактировать» / «❌ Отмена».
   В режиме редактирования можно поправить любое поле, суммы валидируются.
5. При записи бот ищет в колонке C договор с тем же номером (сравнение без учёта
   регистра, пробелов и знаков):
   - **нашёл** → прибавляет оплату к колонке «Оплачено», пересчитывает «Остаток»,
     дописывает пометку в «Примечание»;
   - **не нашёл** → добавляет новую строку из 11 колонок.
6. В ответ приходит номер строки в таблице.

Незаполненные поля пишутся как `[Не указано]` — модель не додумывает данные.
Суммы приводятся к виду `177800000.00`.

## Группа для извлечения ИНН

Отдельный поток, не связанный с личным чатом и регистрацией сотрудников: коллеги
выкладывают в группу договора (фото/PDF/.docx), бот сразу — без карточки
подтверждения — распознаёт ИНН/СТИР контрагента и отвечает результатом.

1. Создайте группу в Telegram, добавьте туда бота.
2. У [@BotFather](https://t.me/BotFather): `/setprivacy` → выберите бота → **Disable**.
   Без этого бот в группах видит только сообщения-упоминания и команды, а не
   обычные файлы — а именно они и нужны здесь.
3. (опционально) Чтобы бот реагировал только в этой группе, а не в любой, куда его
   добавят: узнайте `chat_id` группы (перешлите любое сообщение из неё боту
   [@getidsbot](https://t.me/getidsbot) либо посмотрите в логах бота — `message.chat.id`
   печатается для необработанных чатов) и впишите в `INN_GROUP_CHAT_ID`.

Поведение: если по номеру договора нашлась строка в «Данные» — дописывает ИНН в неё;
если не нашлась — добавляет новую строку с ИНН и контрагентом, остальные поля
`[Не указано]` (пометка в «Примечание», что строка создана из группы).

## Ограничения

- Bot API не отдаёт файлы больше 20 МБ — такие бот отклоняет.
- Старый формат `.doc` (не `.docx`) не поддерживается — `python-docx` его не читает,
  нужно пересохранить в `.docx`.
- FSM хранится в памяти: после рестарта незавершённые карточки теряются.
  Для продакшена подключите `RedisStorage` в `main.py`.
- Альбом из нескольких фото обрабатывается как один документ (первое фото);
  многостраничные документы лучше присылать одним PDF (читаются первые 5 страниц).
- Одновременная запись защищена `asyncio.Lock` внутри процесса. Если запускать
  несколько инстансов бота на одну таблицу, дедупликация может разойтись.
